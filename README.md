### **📚 Bookie** - *FastAPI Microservices Bookstore Platform*

A production-ready microservices platform — 7 independent FastAPI services communicating over **gRPC**, each owning its own database, with no shared secrets or tables.

**Services & Ports:**

| Service | HTTP | gRPC | Owns |
|---|---:|---:|---|
| Auth | 8001 | 50051 | Identity, JWT, password hashing |
| User | 8002 | 50052 | Profiles |
| Follow | 8003 | 50053 | Follow relationships |
| Social | 8004 | 50054 | Likes, ratings, reviews, shelves |
| RAG | 8005 | 50055 | Embeddings + vector search |
| Recommendation | 8006 | 50056 | Profile ranking + recs API |
| Book | 8007 | 50057 | Book/author metadata (MongoDB) |

**Tech Stack:** FastAPI · SQLModel · gRPC (grpcio) · Qdrant · MongoDB · SQLite (aiosqlite) · scikit-learn · pandas · python-jose + passlib (JWT/bcrypt) · pydantic-settings

**Key Design Decisions:**
- ✅ Internal service-to-service calls use **gRPC**, not HTTP — typed, contract-first, ~5–10× faster than JSON
- ✅ Only Auth holds `SECRET_KEY`; every other service validates tokens via gRPC `ValidateToken` — the secret never leaves Auth
- ✅ Refresh tokens rotate on every use, so stolen tokens are single-use and full logout-everywhere is possible
- ✅ Each service owns its own database — no shared tables, no cross-service coupling
- ✅ RAG service handles embeddings/indexing for books & authors; Recommendation service ranks and serves personalized results
- ✅ Full Postman collection with auto-auth pre-request scripting, plus an end-to-end test harness that spins up all services and tears them down

**Status:** Active Development
